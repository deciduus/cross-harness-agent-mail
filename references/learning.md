# Turn observed work into reusable practice

Use this reference when ready work is waiting, an owner reports a workflow
failure, or repeated manual work suggests a tool. Preserve current direction,
actual owners and the smallest useful receiving step.

## Receive ready work and activate the actual owner

For an explicitly prioritized development fix, use one existing integration or
serving owner, pinned inputs, focused receiving/build checks and a rollback
checkpoint. Optional idleness, old WIP counts, a broad audit and routine resource
order do not establish a blocker. Reuse valid checks and current ownership.
A new scope, conflicting live writer, missing dependency, STOP or real permission
boundary still needs resolution. Mailbox claims, fencing and offer/accept remain
required when that mailbox is used.

A saved message is delivery. Activate the intended owner through a verified,
authorized host route and retain its receipt. This package's manual CLI cannot
start a session. If activation is unavailable, return the exact owner, packet,
target and next action to the parent/operator instead of leaving a silent queue
or repeatedly attempting unsupported calls. Known activity stays known when a
downstream receiving ACK is pending; independent authorized work continues.
See [delivery states](handoff.md#delivery-evidence-states).

If the active target has no write grant, prepare the source-pinned patch in an
authorized scratch/receiving workspace while its owner resolves access. Read
permission and scratch write authorization must hold. Preparation grants no
permission to edit the target, bypass a refusal or route a prohibited action
through another agent. Send the pin, minimal diff, applicability/check results
and next owner; the receiver checks its current preimage before applying.

## Keep scheduling and hardware facts separate

An independent queue has its own scheduling owner; it need not have independent
hardware. Keep independent queues moving and coordinate only measured contention
for an actual shared resource. Use current holder/tool/version evidence rather
than historical slot counts or machine assumptions. An urgent authorized fix can
change routine turn order through the current resource owner. This toolkit
implements no hardware allocator, queue scheduler or session activation.

## Make critic feedback useful at a bounded cost

After a major integrated batch, reuse retained critics and existing diagnostics
on the exact served artifact. Focus on affected journeys and controls; a fresh
broad audit is not the default for each hotfix. A concise review includes:

- User motives, control/agency, continuity and discoverability.
- Observed failures, useful ideas, evidence and a named next fix owner.
- Exact source/served identity, relevant checks and native/experience limits.
- Sampling/observation cost and whether the probe distorted behavior.

Summarize on demand and prefer one bounded result over repeated polling turns.
Keep a lag-distorted observation inconclusive; preserve independently reproduced
CPU/source failures. A temporary performance diversion does not permanently
replace the user's content goal or establish experience acceptance.

## Extract guidance, tools and systems incrementally

First inventory existing execution surfaces and actual-use receipts. Reuse the
current schema, exporter, editor, diagnostics or workbench before creating an
alternative with the same responsibility. Host-native prompt review/extensions
may already cover model-era advice; verify availability in the current executor.
A published feature or an installed directory is not capability evidence.

| Repeated need | Reusable home | Evidence for the next increment |
| --- | --- | --- |
| Choosing scope, owners, authority or review depth | Skill guidance | A real decision and its result |
| Exact-byte export, inventory, applicability or receipt steps | Bounded tool | Reproduced output, failure cases, preserved inputs and focused tests |
| Shared behavior needed by several consumers | Existing runtime/system | Receiver use, one source contract and combined checks |
| Repeatable content/world construction | Recipes/data contracts | Provenance, regeneration and the current authoritative schema |

Extract one repeated operation, compare its output to known delivered bytes,
then extend it for another real need. Keep hashes, source pins, rollback and owner
receipts in small deterministic helpers. A source-ready helper awaits admission/
activation until its receiver provides that evidence. This package ships file
mail; source-workflow inventory/correction tools are not bundled and installed
skills are not automatically synchronized.

## Preserve owner edits and decision provenance

Compare active authoritative files, deliberate forwarding entries and historical
snapshots separately. Record raw hashes and retain preimages privately. A
newline-normalized match explains line-ending differences; applying or rolling
back still uses verified raw bytes. Missing versions stay unknown. Observed
working bytes and the recorded Git commit are separate facts.

Prepare a minimal candidate against an exact preimage. If the current owner has
edited the target, preserve that edit and reconcile the correction on its new
base. Partial semantic adoption does not make a stale candidate safe to apply.
Byte equality proves neither owner ACK, client discovery nor native acceptance.
Roll back through the owner only when current bytes still equal the adopted
candidate; otherwise reconcile intervening work.

Record a user correction as scoped durable practice:

```text
Direction revision: <current instruction / prior revision it supersedes>
Authority: <direct user direction / approved plan / unapproved proposal>
Scope and owner: <affected slice / current custodian>
Evidence: <observed result, exact source/artifact and remaining uncertainty>
Reusable home: <guidance / existing tool / runtime contract / recipe>
Disposition: <prepared / partial / adopted / superseded>
Next: <receiving owner and bounded action>
```

A reference document's location does not promote an example or proposal to
approved intent. Keep design references, proposed fiction/plans, approved canon,
user/player history and runtime state distinct where those concepts apply. An
executed event is not retroactive authority for its consequences.

## Evidence behind this update

Authorized internal receipts established active-source copy convergence and
partial coordinator adoption of delivery states, current-direction precedence
and independent-queue semantics. Inventory/correction helpers passed focused
fixtures and prepared minimal candidates; their receiving/activation and other
custodians' candidate adoption remained pending. A stale coordinator candidate
was refused after its owner independently edited the target. Preserve that edit.

An author reported combining repeated export/assembly/identity/receipt work into
an existing tool and reproducing two delivered artifacts byte for byte. These
are bounded source-workflow observations, not universal toolkit automation or
proof that all internal skills were adopted. Approval/proposal classification
still had an unresolved owner-reported source finding at handoff; this text does
not claim that correction landed. Private inventories, paths, identities,
preimages and project payloads remain outside this public collection.
